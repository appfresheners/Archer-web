- (decision) AD-1: Paradigm — Component-based SPA with static export. Binds: all UI is React components. Prevents: server-side runtime, API routes.
- (decision) AD-2: Starter — Next.js 14+ App Router with static export (output: export in next.config). Binds: file-based routing, React Server Components disabled for static. Prevents: dynamic server features.
- (decision) AD-3: State — React useState local to page component. No global state library. Binds: mode, input, output are co-located state. Prevents: Redux/Zustand overhead.
- (decision) AD-4: Template engine — Pure TypeScript functions that accept user input string and return markdown string. No templating library. Binds: templates are deterministic, testable pure functions. Prevents: runtime dependencies for generation.
- (decision) AD-5: Styling — Tailwind CSS utility-first. No component library (Radix, shadcn etc). Custom lightweight components only. Binds: all visual styling via Tailwind classes. Prevents: CSS-in-JS, external UI kits.
- (decision) AD-6: Deployment — Vercel free tier, static output directory. No environment variables needed. No build-time data fetching. Prevents: serverless functions, edge runtime.
- (event) Spine finalized — fast path, hobby/solo stakes, all decisions adopted from brief + UX contract.

- (decision) AD-7: Paradigm (revised) — Server-capable Next.js App Router SPA with Node.js runtime and Supabase backend. Binds: API routes live in /app/api/; all data persisted to Supabase; auth-gated routes under /app/\*; unauthenticated entry via / (Project Mode only). Prevents: static export (output=export), client-side-only data model, localStorage-only persistence for authenticated data.
- (decision) AD-8: Two-layout system — unauthenticated (single-column centered, max 640px, no sidebar) and authenticated (fixed 240px sidebar + max 720px main). The boundary is sign-in/sign-out only; no mid-session layout switching. Binds: all /app/\* routes render authenticated shell; / always renders unauthenticated shell. Prevents: hybrid or dynamic layout selection within a session.
- (decision) AD-9: Data model hierarchy — Goal → Project → Action is the enforced hierarchy. Flat lists are not permitted; an action must have a parent project; a project must have a parent goal. Binds: Supabase schema, UI navigation structure, Engage view logic (shows committed actions, not raw task lists). Prevents: standalone action creation without a project, project creation without a goal (except wizard abandonment, which creates nothing).
- (decision) AD-10: Single committed next action per project — at most one action per project can be in committed status at a time. Committing a new action automatically decommits the prior one. Binds: action commit logic, Engage view (shows committed only), stuck-project detection (Active project + zero committed = stuck). Prevents: multiple committed actions per project, implicit task queue behaviour.
- (decision) AD-11: AI generation contract — two call patterns share the same /api/generate route infrastructure. Pattern A (Project Mode, existing): POST {input, mode:'project'} → markdown string. Pattern B (Wizard Step 1, to build): POST {goal, step:'framework'} → skill framework JSON. Pattern C (Wizard Step 4, to build): POST {goal, framework, ratings, drivers, barriers, ifThen, mode:'goal'} → full breakdown markdown. Provider selected by AI_PROVIDER env var (gemini|groq|openai). All calls have 30s timeout. Binds: route handler shape, wizard Step 1 and Step 4 payloads. Prevents: client-side AI calls, provider coupling in component layer.
- (decision) AD-12: AI provider invariant — AI never infers user ratings, drivers, barriers, or if-then plan content. These fields come exclusively from user input (wizard steps 2–3). AI proposes required levels (target profile) and generates the breakdown from structured user inputs. This is a system-wide constraint that affects every surface touching gap data. Binds: wizard step 1 (framework proposal only), step 2 (user rates, AI silent), step 3 (all user content), step 4 (AI receives structured inputs verbatim). Prevents: any pre-fill, inference, or suggestion of current ratings or barrier content.
- (decision) AD-13: Auth boundary — Supabase Auth gates all /app/_ routes. Unauthenticated users access / (Project Mode) and /sign-in, /sign-up only. Goal creation wizard (/app/goals/new) requires auth. Vault is auth-independent (client-side, always accessible). Binds: Next.js middleware auth check on /app/_ routes; Supabase client initialisation in app shell. Prevents: unauthenticated access to goals/projects/actions/review/engage data.
- (decision) AD-14: Supabase schema — core tables: goals, projects, actions, inbox_items, review_sessions, weekly_snapshots. Relationships: projects.goal_id → goals.id; actions.project_id → projects.id; inbox_items.user_id → auth.users; review_sessions.user_id → auth.users. Row-level security (RLS) on all tables: users can only read/write their own rows. Binds: all data persistence FRs (78–81), weekly review state preservation (FR73), export shape. Prevents: cross-user data leakage, clientside-only data model for auth'd data.
- (decision) AD-15: Wizard state — multi-step wizard state (steps 1–4: goal text, framework items, ratings, drivers/barriers/ifThen) is held in client component state for the duration of the wizard session only. It is NOT persisted to Supabase until generation succeeds (Step 4). Abandoning the wizard discards all state. Binds: wizard component tree, FR4. Prevents: auto-save of partial goals, recovery/nudge flows.
- (decision) AD-16: Weekly review state preservation — an in-progress weekly review session (phase progress, snapshot fields, inbox processing position) IS persisted to Supabase so the user can leave and return without losing progress. A review session row is created when the review begins and updated on each phase transition. It is marked complete only when the closing snapshot is saved. Binds: review_sessions table schema, weekly review UI phase transitions (FR73). Prevents: losing review progress on browser close.
- (decision) AD-17: Vault independence — the experimental vault (client-side, AES-GCM + PBKDF2, localStorage) operates independently of Supabase auth. It is accessible to unauthenticated users and persists across sign-in/sign-out. It is never merged with or replaced by Supabase persistence. Binds: vault UI always accessible from header regardless of auth state; vault crypto lives in lib/vault/. Prevents: vault data ever being transmitted to a server; vault being removed when Supabase layer ships.
- (decision) AD-18: Responsive layout breakpoints — mobile (<640px): single column, bottom nav; tablet portrait (640–768px): single column, bottom nav; tablet landscape (768–1024px): 56px icon-only sidebar; desktop (>1024px): full 240px sidebar. Unauthenticated layout: always single-column max 640px regardless of breakpoint. Binds: authenticated app shell, sidebar collapse behaviour. Prevents: sidebar showing on mobile.
- (decision) AD-19: Markdown rendering — react-markdown + remark-gfm + rehype-raw required for output panels. rehype-raw is mandatory for <details>/<summary> accordion rendering in goal breakdowns. Binds: OutputPanel component, goal detail project accordions. Prevents: stripping HTML tags, using a different markdown renderer.
- (decision) AD-20: No copy/download in authenticated views — Copy Markdown and Download .md buttons exist only on the unauthenticated landing output panel. In authenticated views, breakdowns are saved directly to Supabase on generation. Vault is the persistence path for unauthenticated users. Binds: ActionBar component (unauthenticated only), OutputPanel in auth'd shell. Prevents: duplicate persistence paths for authenticated users.
- (constraint) Tech stack locked by PRD §7: Next.js 16 (App Router, Node.js runtime), Tailwind CSS v4, Vercel (Node.js), Supabase (Postgres + Auth + Realtime), Web Crypto API (vault), qrcode lib (client-side SVG only), no analytics.
- (constraint) AI_PROVIDER env var must be set; no hardcoded model fallbacks. GEMINI_MODEL, GROQ_MODEL, OPENAI_MODEL each required when their provider is selected.
- (constraint) No streaming AI responses in v1 — generation is single-shot request/response.
