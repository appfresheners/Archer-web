topic: Archer GTD Goal & Project Creator UX
updated: 2026-09-27T15:35
---

- (decision) Product name: Archer. Single-page web app, two modes: Goal Mode (full GTD pipeline) and Project Mode (lighter breakdown).
- (decision) Form factor: web (responsive, mobile-friendly). Tech: Next.js + Tailwind, deployed to Vercel. Zero backend.
- (decision) Primary CTAs: Copy Markdown, Download .md. Output is Notion-optimized markdown.
- (decision) Zero friction: no account, no auth, no tracking. Free forever public tool.
- (decision) MVP1: No AI/LLM. Pure template generation with user input slotted in. Single text input per mode.
- (decision) Working mode: Fast path selected. Batch assumptions, skip creative tools.
- (assumption) Stakes: passion project / public good. No regulated content, no payments, no PII.
- (assumption) UI system: Tailwind utility-first with no component library (shadcn, MUI, etc.) specified. Assuming custom lightweight components.
- (event) Fast-path draft complete. Both DESIGN.md and EXPERIENCE.md drafted with [ASSUMPTION] tags for user review.
- (change) Full overhaul of both spines triggered by PRD update (v1-full, updated 2026-09-27). Scope expanded from single-page generation tool to full GTD system.
- (decision) Architecture: unauthenticated single-column layout retained for Project Mode generation tool; authenticated layout uses fixed 240px sidebar. Two distinct layout modes, not one.
- (decision) Backend: Supabase (Postgres + Auth + Realtime) replaces the prior zero-backend assumption. Node.js runtime confirmed (not static export). Vault remains client-side only, independent of Supabase layer.
- (decision) Goal creation: 4-step wizard replaces single text input for Goal Mode. Steps: Goal & Skill Framework → Gap Rating → Drivers & Barriers → Review & Generate. Wizard abandonment discards partial state — no auto-save.
- (decision) AI never infers gap ratings or barrier content. All user ratings start at 5 (neutral midpoint) and are dragged by the user. Drivers, Barriers, and If-then plan are blank until user types — AI does not pre-fill.
- (decision) New surfaces added to IA: Goals list, Goal detail, Project detail, Inbox, Engage, Weekly Review (3-phase), Monthly Goal Check, Settings. Project Mode generation tool retained as unauthenticated entry point.
- (decision) Engage view is default post-login view. Shows only committed next actions. No Kanban, no full action list, no project tree. Completing an action immediately prompts for the next committed action from that project so it never silently goes stuck.
- (decision) Stuck projects (Active + zero committed actions) are always surfaced — in Engage, in Weekly Review Get Current phase, and in Goal detail. Never hidden. Amber warning treatment. Weekly Review cannot advance past a stuck project without resolution.
- (decision) Typography: JetBrains Mono added for generated markdown output only (signals artifact, not interface). Inter remains for all UI copy. Added to DESIGN.md token set.
- (decision) Color palette extended: amber (warning/stuck), red (destructive/archive), status badge colors (6 statuses), wizard step states added. Primary blue and emerald success retained from prior draft.
- (event) Both spines fully updated to match PRD v1-full (2026-09-27). Status remains draft — Reviewer Gate and Finalize not yet run.
- (change) Flow 1 (Thembi breaks down her first goal) removed. It demonstrated static goal generation to Notion — both now invalid. Replaced with new Flow 1: Thembi creates her first goal through the wizard (authenticated, no Notion, no static template).
- (decision) Static goal generation is retired. Goal Mode = 4-step wizard only. The prior /api/generate + goal-template.ts single-shot flow (AI guessing user current ratings) is structurally wrong and will not be retained. All goals go through the wizard.
- (decision) AI does not know the user's level. Stated as a system-wide invariant in Foundation, GTD Template Integrity, and all wizard step specs. AI proposes required levels only; user provides all current ratings. This constraint is non-negotiable.
- (decision) Notion removed as system of record. Archer holds all GTD data. No copy/download CTAs in the authenticated system. No 'Notion-optimized markdown' framing anywhere. No flows that treat Notion as the destination.
- (decision) Copy/Download buttons removed from the product. Unauthenticated landing: vault is the persistence path. Authenticated: data saves to Supabase on generation. No clipboard or file export actions anywhere in the authenticated system.
- (decision) Mode toggle removed from unauthenticated landing. Project Mode is the default and only unauthenticated mode. No Goal/Project toggle on the landing page. Sign-in CTA nudges toward account creation for goal access.
- (decision) Project Mode template updated to use Allen's Natural Planning Model: Purpose → Principles → Successful Outcome → Next Actions. Principles (standards/constraints governing execution) are a required section. Prior template was missing this layer.
- (event) EXPERIENCE.md and DESIGN.md updated to reflect: wizard-only goal creation, AI level constraint, Notion removal, copy/download removal, mode toggle removal, Allen Natural Planning Model for projects.
- (decision) Weekly Snapshot added to Weekly Review. Two bookend beats wrap the 3-phase review: Opening (retrospective — what actually moved last week) and Closing (forward intention — what matters most + primary blocker). Both required, both free text prose. Cannot complete review without both.
- (decision) Weekly Review phase bar updated from 3 phases to 5 beats: Snapshot (open) → Get Clear → Get Current → Get Creative → Snapshot (close). Snapshot beats are visually distinct (narrower) — bookends, not phases.
- (decision) The Notion weekly planner (intention / blocker / what moved columns) is superseded by the Weekly Snapshot. Root problem identified: no loop closure — same intention repeated across weeks 37/38/39 because there was no retrospective before the next intention. Snapshot enforces the loop: opening retrospective must be written before closing intention is shown.
- (decision) Weekly Snapshot is NOT a planning tool. It does not replace committed next actions. It is the human context layer: one retrospective sentence and one intention sentence per week, stored so the system has memory. The Engage view remains the actual plan.
- (decision) Weekly Review session content model extended: opening retrospective, closing intention, closing blocker, week number, week date range — all stored per review session in Supabase.
- (event) Weekly Snapshot added to EXPERIENCE.md (Weekly Review section, Flow 3, Voice and Tone, content model) and DESIGN.md (Phase Bar component). Research basis: David Allen's Get Creative phase + implementation-intention research. Not canonical GTD — a deliberate extension.
